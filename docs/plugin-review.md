# Eagle 摄影筛选助手（统一插件）

## 固定入口

用户只需要在 Eagle 开发者模式加载：

```text
D:/Photography/PhotographyOperations/EagleCullingPipeline/src/plugin
```

插件名称和 ID 固定为“摄影筛选助手 / EAGLECULLING001”。旧的 `src/thumbnail-bridge` 保留兼容周期，但不再需要单独加载。以后更新只替换 `src/plugin` 内容，在插件的“设置 / 诊断”点击“重载当前插件”即可，不需要重新创建窗口插件。

## 四个区域

- **概览**：当前选择、审阅统计、本地服务状态、旧角标清单迁移提示。
- **审阅**：精选、候选、待复核、问题标签、相似组、JPG/RAW/HEIC/3FR 配对和中文原因。
- **任务**：分析进度、暂停、继续、仅重试失败、明确选择的旧角标恢复；非日常的缩略图写入/备份恢复在折叠兼容区域。
- **设置 / 诊断**：即时插件角标显示开关、自定义并发、请求间隔、服务版本、诊断报告。

## 任务队列

审阅卡片支持左下角中文角标；“显示左下角审阅角标”只切换插件显示层，立即生效，不重写 Eagle 缩略图。它与历史写入 Eagle 网格的角标是两种机制。

“审阅时同步一对一同名 RAW/JPG、3FR/HEIC”默认开启：即使只选 JPG，也会查询全库目录，确认唯一配对后同步 RAW 状态。重名或文件夹冲突只处理本张。相似组的“设为组内首选（成对留存）”需确认，本次拍摄设为精选、其余待复核，不删除或改星级。审阅任务按成员记录断点，部分失败可继续，不宣称多文件原子事务。

AI 分析按确认配对合并计算：同次拍摄只分析一份 JPG/HEIC 预览，各已选文件分别显示结果和自身元数据；RAW 的代理分不代表原始动态范围、RAW 解码效果或原片级清晰度鉴定。相似组数量按分析单元统计，同时展示对应文件。模型不可用会进入“需重点检查”，不能据此判断没有闭眼。断点恢复保留当前人工元数据，过期缓存标为历史结果。

插件不再由按钮直接启动不可恢复的全库循环，而是先把任务写入本地服务的 `data/tasks.json`。任务记录包含：

```text
taskId taskType createdAt updatedAt libraryPath manifestVersion
itemId modifiedAt status attempts outputPath error
```

状态为 `pending/running/succeeded/skipped/failed/paused/cancelled`。任务总张数不设硬阈值。默认并发 8、请求间隔 0ms；可输入任意正整数并发（例如 16/32），设置会保存。单项最多重试 3 次，每完成 25 项持久化断点。已有任务暂停后，修改设置再继续会应用新的并发/间隔。Eagle 或插件重启后，已完成项目自动跳过，未完成项目继续；失败项可单独重试。取消不会撤销已完成操作，不会继续写回剩余项目。

新版执行权控制：同资源库只允许一个窗口推进任务。正常“重载当前插件”先暂停、等待在途请求完成、保存断点并释放执行权，再重载。异常退出后不会仅凭心跳超时自动抢占；请关闭旧窗口，在任务记录中选择该任务，点击“释放失联执行权”（30 秒无心跳后可用），确认后点击继续。该操作不撤销标签、不恢复缩略图。旧服务缺少 `task-execution-v1` 时，新插件不会启动写回任务，需先等待旧任务结束后更新服务。

服务接口：

```text
GET  /health                 GET  /version
GET  /tasks                  POST /tasks
GET  /tasks/:id              POST /tasks/:id/pause|resume|cancel|retry
POST /tasks/:id/progress     POST /tasks/:id/checkpoint
POST /tasks/:id/complete|fail
POST /analyze                POST /badge-thumbnail
GET  /badge-manifest
```

固定启动入口：

```powershell
D:/Photography/PhotographyOperations/EagleCullingPipeline/scripts/start-service.ps1
```

脚本先探测 `127.0.0.1:43125`，服务已运行时不会重复启动；服务未运行时以隐藏后台进程启动 `npm run serve`。

## 显示开关与历史缩略图维护分开

Eagle 官方 API 没有独立的网格角标层和原生大图预览层。日常审阅不通过修改 Eagle 缩略图实现标签显示：

1. **插件角标显示（默认显示）**：设置中的“显示/隐藏角标”与审阅复选框同步，切换 CSS 显示层，在离线或后台分析期间也能使用，不创建任务、不修改 Eagle 文件或元数据。刷新后保留显示设置。
2. **旧网格角标恢复（独立维护）**：明确选中旧角标照片，在任务页点击“移除所选旧网格角标（重建预览）”，确认后创建可恢复任务。显示开关不会移除历史网格角标，界面不再声称设置已证明整库恢复原生状态。

“兼容维护”默认折叠，保留历史缩略图写入及登记备份恢复，以便处理旧任务。生成新网格角标需确认逐项写入及高清预览风险；日常分拣不推荐使用。固定 ID/目录不变，不要求重新安装才能找到这些操作。

恢复时插件读取当前资源库的成功任务记录，只对成功写回且尚未恢复的 ID 调用 `Item.refreshThumbnail()`。旧生成清单不作为恢复凭据。若用户在写回角标后更改了项目，`modifiedAt` 防护会跳过该项目。角标不会写入 JPG、RAW、HEIC 或 3FR 原片。

## 中文审阅与配对

审阅卡片将原因码转换为中文：清晰度偏低、闭眼、过曝、欠曝、相似组首选、RAW/原始格式母片保护、已配对、配对待确认和基于预览图。标签写回只替换 AI 审阅状态，保留人工标签、质量标签、配对标签、星级和文件夹。

JPG/HEIC 与同名 RAW/3FR 一对一匹配时，成片审阅状态可通过显式命令同步到 RAW；不确定的重复基名不会猜测配对。RAW 默认作为母片保护，不会因为 JPG 更好看而建议删除。

## 启动与使用

```powershell
cd D:/Photography/PhotographyOperations/EagleCullingPipeline
npm install
npm run start-service
```

在 Eagle 中选择照片后打开插件，先点“AI 分析所选照片”，再在“审阅”中人工确认。需要全库角标时进入“任务”创建任务，不要直接修改 Eagle 资源库内部文件。没有自动删除按钮；删除或回收由用户在 Eagle 中完成。

## 旧数据迁移

兼容维护区域的“恢复登记缩略图备份”只处理有备份且指纹匹配的工具登记缩略图，无备份或指纹不匹配时跳过，不自动重建。它仍属自定义缩略图，不保证原生高清预览，不是日常显示开关。详见 [历史角标恢复](thumbnail-fast-restore.md)。

### 立即移除旧版左上角角标

1. 在 Eagle 主窗口选中需要移除旧角标的照片，建议先选 1 张。
2. 打开统一插件 → 任务 → **移除所选旧网格角标（重建预览）**。
3. 核对确认框中的数量和文件名，确认后创建可暂停、续跑、取消和重试的恢复任务。不限制任务总张数，无需手动分批。

此操作允许用户明确选择的旧角标照片绕过历史归属清单限制，不自动扫描或恢复未知项目。它调用 `refreshThumbnail()`，不删除原片、不写标签/星级/文件夹，但会替换所选照片原有的人工自定义缩略图；Eagle 同时会刷新尺寸、颜色等缩略图派生信息。左上角 HEIC/3FR/JPG 等原生格式标识不会移除。操作成功后 AI 标签仍保留。

第一次连接服务时，插件检查旧版 `data/thumbnail-badges.json`，目前仅显示清单数量并保留现状。生成 PNG 不等于已写入 Eagle，故旧清单不会直接授予恢复权限。历史角标的人工归属确认/导入迁移尚未实现。恢复只依据当前资源库内成功的新版写回任务，并扣除已成功恢复的项目；不会根据另一资源库的同名 ID 操作。

## 开发者模式与验收

Eagle：插件 → 开发者选项 → 导入本地项目 → 选择上述固定 `src/plugin` 目录。后续更新使用同一目录，不重复创建插件。`manifest.json` 默认 `devTools: false`，需要排错时再打开开发者工具；正常审阅不显示右侧调试面板。

验收顺序：20 张混合 JPG/RAW/HEIC/3FR → 500 张混合项目 → 全库约 8,000 项。需要验证任务暂停/继续、Eagle 重启后断点、失败重试、`modifiedAt` 变化跳过、原片 SHA-256 不变、人工标签/星级/文件夹不变，以及原生模式清晰度和角标模式左下角位置。

自动测试覆盖：53 项 Node/Edge 测试，包括服务健康与版本、任务 API 生命周期与配置更新、分析结果持久化、8,000 项并发 1/2/4/8/16/32/48 模拟、8,000 张恢复选择、瞬时失败重试、暂停后继续、断点错误不重复执行写回、跨库恢复隔离、中文审阅筛选和模拟 Eagle `Item.save()` 非破坏性写回。新增 8,000 项并发 128 的批量读取模拟、缺失项目、读取失败恢复、重试时重新读取和恢复后增量统计。这不是 8,000 次真实 Eagle API 的性能验收，高并发的真实吞吐量和资源峰值仍需验收。

### 批处理与高并发

任务总张数不设上限。并发读取在同一事件循环窗口合并，使用官方 `getByIds()`，内部每个读取批次最多 256 个 ID（仅传输批次，不是任务数量或并发限制）。不跨重试缓存 Item；仍检查项目修改时间和资源库路径。旧版 API 缺少批量读取时退回单项查询。

8,000 项、并发 128、即时模拟处理条件下，仅需 63 次元数据读取。恢复任务续跑不再先加载全库；计数采用增量更新，任务进度界面最多每 250ms 更新一次。断点仍每 25 项持久化，未改变恢复安全范围。

官方公开 API 的 `refreshThumbnail()` 是单 Item 方法，没有公布批量重建接口；128 个请求不等于 Eagle 同时启动 128 个 RAW 解码线程。上述优化减少插件开销，不保证原生缩略图重建同比提速；目前未做真实 Eagle 重建吞吐量与资源峰值压测。不会通过直接修改资源库文件绕过 API。

更新正在执行的插件：先暂停，等待当前调用完成并显示 paused，再使用设置/诊断里的重载插件，然后继续原任务；无需重新导入目录或创建新任务。服务无需为本次前端更新重启。

当前限制：插件关闭后不继续 Eagle 写回；生成/写回仍由插件驱动，服务持久化任务而非独立后台执行。执行权、多窗口防重、远程暂停/取消传播已通过自动测试，但实际 Eagle 验收未完成。异常退出留下执行权时不自动抢占，需确认旧窗口关闭后释放失联执行权；不提供恰好一次写回保证。旧角标归属迁移、更新检查、安全无感升级、真实 Eagle 三阶段验收尚未完成。未经归属确认的旧角标保持原状，因此界面“原生模式”不意味着整库历史角标都已恢复。

### 资源调度与评分缓存（2026-10-09）

API 并发与图片处理并发分开。服务默认最多 4 个解码任务、2 个常驻人脸模型进程（按 CPU 调整解码数），可用内存不足时暂停接纳新解码。设置/诊断显示实际解码数、排队数、每图线程、服务 RSS 和可用内存。`EAGLE_IMAGE_WORKERS` 与 `EAGLE_IMAGE_THREADS` 用于服务启动配置，不等同于插件请求并发。内存预算是软准入策略，不是硬内存上限。

暂停/取消会撤销尚未开始的图片处理和模型任务；已经开始的本地推理可能完成，已经发出的 Eagle 写回必须等待返回，不能承诺立即中断。

小预览尺寸不作为原片低分辨率扣分依据。只有实际读取原图时才核验原片尺寸。历史评分保存算法版本，升级后旧评分明确显示过期，不用于当前留存推荐。RAW 复用配对预览评分时，还检查预览来源的修改时间；来源缺失、变更或无法核验时要求重新分析。人工标签和星级不会因评分失效自动改变。

分析返回后再次读取配对成员和来源，期间修改或删除项目会跳过迟到结果，并刷新当前人工状态。过期分析可在“需重点检查”筛选集中查找，不自动改变人工留存标签。

当前完整自动测试为 94/94 通过、0 跳过（包含 Node 与隔离 Edge 模拟）。资源基准及实机未完成事项见 [稳定性验收记录](stabilization-plan.md)。以上实现尚未替换仍在运行的旧服务，不能据此认为当前 Eagle 窗口已启用全部功能。

最新测试计数为 96/96。真实 20 文件只读抽样零分析失败，原片 SHA 与元数据字节均不变，但未做真实写回或人工准确率标注。评分现在明确标注“粗排参考分”：构图/主体只是纹理、对比度启发式，不是经过验证的审美模型；不再输出未经校准的固定置信度。详细证据与限制见上述验收记录。

## 官方 API 依据

### 导出进度与异常清单

任务页新增“导出当前任务报告 JSON”和“导出异常与未完成清单 CSV”。两者先读取完整服务端断点，只读导出，不保存 Eagle 项目，不要求停止正在运行的任务；运行中导出的是当时快照。JSON 记录全部单元及原因，CSV 保留所有失败、跳过和待处理等非成功单元，不限行数。

报告分别统计任务单元与涉及文件数。处理结束比例包括成功、跳过和失败，成功比例单列；100% 处理结束不表示恢复全部成功。成对标签部分写回只报告断点已记录的 `appliedIds`，不推断其余成员也成功。CSV 为 UTF-8 BOM、中文表头，转义引号/换行并保护以公式符号开头的文本。报告不替代原片 SHA、预览清晰度或人工元数据实机验收。

即使旧服务尚未更新，也可在项目目录只读导出：`node scripts/export-task-report.mjs <task-id>`。输出到新的临时目录，不修改旧任务。最新完整测试为 107/107；实际旧恢复任务导出得到 19 个待处理与 14 个跳过，共 33 行异常/未完成记录。

当前待启用版本为 0.4.0（完整测试 103/103）。设置/诊断显示插件与实际服务版本；旧服务或能力不匹配时可以查看状态，但不能启动新任务。`scripts/start-service.ps1` 同样校验版本，不会把仍在运行的 0.3.0 当作已更新，也不自动杀进程。固定 ID/目录保持不变，安全结束旧任务后更新服务、重载现有插件，无需重新创建入口。实机迁移及旧角标恢复仍未完成。

最新分组修复：pHash 与语义向量均要求组内每两个成员满足相似条件，不把相似链条直接合并成“只留一张”的组。缺失 SHA 不作为重复证据，向量维度不一致不比较公共前缀。插件仍只提供留存建议，必须人工审阅，不自动删除。最新完整测试为 101/101；合成 pHash 基准和实际未完成事项见稳定性验收记录。
