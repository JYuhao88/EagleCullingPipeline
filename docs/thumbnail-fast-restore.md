# 历史网格角标恢复与原生重建

## 日常显示与维护操作不同

- **显示/隐藏插件角标**：日常使用，审阅复选框或设置按钮即时切换 CSS；不写缩略图、不创建任务，不影响 Eagle 网格历史角标。
- **恢复登记缩略图备份**：任务页折叠兼容维护中的独立写回操作。只处理本库成功登记的角标；核对当前缩略图指纹及备份 SHA-256 后，调用 `setCustomThumbnail()` 写回备份。不调用 `refreshThumbnail()`，不解码原片、不调用 `save()`。
- **移除所选旧网格角标（重建预览）**：明确选择并确认后调用 `refreshThumbnail()`。用于没有干净备份的旧角标，或需要退出自定义缩略图机制的照片。会刷新尺寸、颜色等派生信息，并替换原有人工自定义缩略图。

快速恢复不主动写原片、人工标签、星级、文件夹或尺寸，但不能保证 Eagle 自身完全不更新内部元数据。无角标备份模式仍属自定义缩略图，不保证原生单图高清预览，界面明确标示，待真实 Eagle 验收。

## 备份与保护

备份在项目 `data/thumbnail-backups/`，不在 Eagle 资源库。目录以资源库路径和项目 ID 的 SHA-256 分隔。保留原缩略图字节、格式、路径、时间与校验值；已有备份不覆盖。

生成角标始终以备份为输入，避免叠加。历史清单及成功角标任务提示污染风险；没有备份且来源不确定时拒绝生成，先明确重建一次。已有人工自定义缩略图会原样备份，因此“干净”表示本工具生成角标前的状态，不保证它原本是原生缓存。

写回角标后记录 Eagle 实际缩略图的指纹，考虑 Eagle 可能重新编码输入。快速恢复时指纹不同则跳过，避免覆盖后来的人工修改。无指纹、无备份、跨库、备份损坏均不自动转为慢重建；界面保留跳过或失败原因。

备份不自动清除，只复制小缩略图，不复制 RAW。固定保留首份备份；同 ID 原片后来编辑时，应人工检查旧备份是否适用。新版有同库执行权防重，异常退出不会自动抢占；旧服务尚未启用这项保护，不要并行操作同一项目。

## 更新与使用

### 纠正：原生重建也可通过官方 Web API

此前把原生重建限于插件 `Item.refreshThumbnail()`，因此把缺少桌面控制通道误当成无法程序化恢复的接口限制。最新[官方 Web API V2 Item 文档](https://developer.eagle.cool/web-api/api/item)明确列出 `POST /api/v2/item/refreshThumbnail`，请求体是 `{ "itemId": "..." }`。旧 [V1 接口](https://api.eagle.cool/item/refresh-thumbnail)为 `/api/item/refreshThumbnail`、字段 `id`；不能混用字段或路径。恢复不必依赖 Computer Use，也不应直接改库内文件。

`EagleApi.refreshThumbnail(itemId)` 已实现 V2 调用，只提交 itemId，不提交人工标签/星级/文件夹或原片替换。API 成功只是响应确认，不是恢复效果验收；仍须原片 SHA、人工元数据、缩略图及单张预览检查。官方说明重建会更新尺寸/颜色等派生信息，不能承诺完全不改元数据或所有格式立即完成。

新增 `src/native-restore.js` 的 `restoreNativeVerified` 操作校验：必须提供明确资源库、项目、计划修改时间、原片 SHA-256 读取器及写前执行权 guard；缺少任何项拒绝运行。调用前分阶段核对库、项目和修改时间，哈希期间发生项目变化则跳过；调用后检查原片 SHA 及名称/格式/标签/文件夹/星级/备注/来源链接，允许重建产生的尺寸变化。标签/文件夹按集合排序比较，不把 API 返回顺序变化当数据丢失。

这个组件是操作校验器，不是已经投入生产的独立恢复执行器。调用者仍须确认旧窗口关闭、领取并维护持久执行权、将真实原片路径与该项目绑定、持久化逐项结果并处理不确定结果；该组件不会代办这些步骤或写原片/元数据文件。检查无法锁住用户切换 Eagle 资源库或外部编辑的所有时刻，不声称多请求事务原子性。

调用后失败一律 fatal/unknown，当前队列停止而不是再发请求或回滚人工字段；已经在途的其他请求仍需等待排空。返回 `previewVerified=false`，即便尺寸回到原尺寸量级，也不能宣称角标/高清视觉验收通过。模拟测试覆盖修改、切库、丢失响应、原片/人工字段变化，验证不发首个危险写入、每项最多一次恢复调用；完整回归 144 项。本轮没有调用真实 Eagle 恢复接口。

网络超时/异常/明确负值返回均按恢复结果不确定处理，设置 fatal，禁止队列自动重试；HTTP 客户端停止观察不代表 Eagle 内部操作已停止。必须先核查再人工决定是否重试，不能同时发第二次重建来“试一下”。此方法尚未在真实库执行，不能声称本机接口已恢复成功。

2026-10-09 最新只读核对：旧恢复任务仍登记 running，7,961 成功、14 跳过（当前目录中缺失）、19 pending。19 项均存在；5 个 HEIC 当前记录为原尺寸量级，7 对 JPG/DNG 当前仍记录 320×480 或 480×320。pending 不是证明从未执行，原尺寸也不是证明已去除角标/恢复高清；应逐项核验，不重复跑已完成的 7,961 项。旧窗口关闭及在途操作排空仍需确认，不能凭检查点长期不变就抢占执行。单元覆盖 V2 参数、响应确认、非法 ID、异常不自动重试；完整回归 140 项。生产服务仍 0.3.0，本轮没有恢复照片或重启服务。

1. 旧任务运行时先暂停，等待当前调用结束、显示 paused，不要强行重启服务。
2. 安全结束旧任务及在途请求后更新项目分析服务；`GET /version` 必须满足插件 0.4.0 的完整版本/能力契约。启动脚本不会自动替换不兼容的旧进程。
3. 设置/诊断 → 重载当前插件，无需重新导入目录。
4. 日常分拣只使用插件角标开关，不为验证显示效果而给照片重新烧入角标。
5. 需要清除已有旧网格角标时，先对一张明确选中的旧角标照片执行恢复，检查网格、单张预览、原片 SHA 与人工元数据，再扩大范围。无干净备份时仍需原生重建。

任务总数不限，仍支持暂停、继续、重试。快速隐藏避免 RAW 解码，但 Eagle 每项写回仍有开销，不承诺 8,000 张秒完成。

## 验证

57 项自动测试通过，包括备份字节一致、重复生成不覆盖、并发捕获、跨库隔离、损坏校验、RAW 来源拒绝、人工修改保护、服务往返及模拟 Item 不调用重建/save、不改人工字段。另有 8,000 项批量读取和并发队列模拟。

未完成：真实 Eagle 20/500/8,000 张吞吐、资源峰值、JPG/RAW/HEIC/3FR 高清预览及 Eagle 内部元数据变化验收。模拟测试不替代这些检查。

## macOS 与 Computer Use

支持地区的 macOS、Windows 都可使用 Computer Use。macOS 支持限定范围后台操作与可选锁屏使用；Windows 在活动桌面前台操作，会占用同一桌面会话。这改善界面操作体验，不改变 Eagle 缩略图 API 的速度。

当前 manifest 是 win/x64，启动脚本是 PowerShell，模型未做 Mac 验收，不能声称已支持 Mac。本会话未提供可调用的桌面控制运行时，更换系统不保证当前会话能操作界面。
