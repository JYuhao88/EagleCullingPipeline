# 固定入口的服务检查与安全升级

## 用户入口

只使用 `src/plugin` 的“摄影筛选助手”。更新后继续重载同一入口，不卸载、不创建新插件、不清空本地设置。旧 `thumbnail-bridge` 不是新版入口。

插件“设置 / 诊断”增加“重新检查服务”和服务检查与升级说明。重载插件更新窗口代码，不会替换正在运行的 Node 服务；重启 Eagle 也不等于重启该服务。

## 状态与诊断

`service-status.js` 并行只读请求 `/health` 和 `/version`，各有 1,800ms 超时；定时检查和手动检查复用一个在途检查，不重叠发起同类探测。

| 显示 | 判据 | 行为 |
| --- | --- | --- |
| 本地服务未连接 | 两个请求都没取得 HTTP 响应 | 可能未启动或超时，不凭连接失败推定进程不存在 |
| 本地服务异常 | 端口有响应，但健康状态、服务身份或版本响应无法确认 | 显示错误；不启动第二个服务，不将健康失败误报为未启动 |
| 服务版本不兼容 | 健康通过，版本/API/capabilities 不满足插件契约 | 暂不启动新任务，显示升级说明 |
| 已连接 | 健康 `ok=true`、服务身份正确、版本契约一致 | 服务检查通过；不等于所有模型或真实照片准确率已经验收 |

HTTP 503、`ok=false`、未知服务、非法 JSON 和版本请求失败均不会被当作可用服务。非数组 capabilities 按缺失处理，不使界面检查崩溃。诊断导出前重新检查，记录原始 HTTP 状态、健康/版本响应、错误、检查时间、缺失能力；不只记录旧缓存中的任务数。报告仍可能含资源库路径/文件信息，发送给他人前需要检查隐私。

## 升级顺序

1. 旧窗口若有任务，先暂停并等当前请求结束。进度长期不变不能证明请求已停止。
2. 关闭旧插件执行窗口，确认无在途操作后再退出旧本地服务。不要对仍在执行的进程强制结束。
3. 在项目目录运行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-service.ps1`。脚本会拒绝重复启动、旧版本和端口占用；不会自动杀进程。
4. 点击“重新检查服务”，确认版本一致；重载同一插件入口，在原资源库继续断点。

目前没有从未知旧版本自动证明其写入已排空的控制协议，所以不能提供无条件“强制升级”按钮。本实现不偷偷停止服务、不修改任务、不重建缩略图。旧网格角标是写进缩略图的像素，必须另行恢复；插件 CSS 角标显示开关可瞬时生效，不修改照片或元数据。
