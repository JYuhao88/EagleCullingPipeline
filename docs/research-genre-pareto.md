# 类别化选片与 Pareto 候选集调研（2026-10-09）

> 状态：调研与方案设计，**尚未实现**。本文是后续推进的依据；结论中凡标「推断」「待验证」的部分，都需要用户标注数据确认。
> 来源：本仓库源码与测试库实测、Codex 独立分析、论文库检索（`ml/research/search_genre_corpus.py`）、既有 [research-culling.md](research-culling.md)。

## 1. 问题

用户质疑：现在的选片方式是否科学？照片的好坏不是单一维度——有的模糊但很有美感，有的清晰但呆板；没把人拍好看的纯人像确实该省去。能否按街拍、人像、风光等分类，在类别内评分，并用类似 Pareto 集合的方式保留「各有所长」的照片？

结论：**质疑成立**。现有排序可以当技术质量基线，但还不是经过验证的「好照片」选择器。建议改为：

**类别识别 → 类别内硬门槛 → 少量目标上的 ε-Pareto 候选 → 候选内按类别偏好排序与人工选择**，并允许「整组都不合格」。

## 2. 现状诊断

### 2.1 排序是补偿式加权平均

`src/core/ranking.js` 对清晰度 0.3 / 曝光 0.2 / 睁眼率 0.15 / TOPIQ-NR 质量 0.2 / 美学 0 加权平均（`ranking-weights.json`，manual-v1），只使用全组都有值的指标并重新归一化权重。

- **补偿性**：曝光或质量上的优势可以抵消主体失焦、表情失败。
- **美学权重为 0**：TOPIQ-IAA 在 Mac 上 442–481 ms/张，超过 400 ms 门槛（见 [model-eval.md](model-eval.md)），所以「模糊但有美感」在结构上没有任何保留通道。
- **TOPIQ-NR 是技术质量模型**（噪声、失真），不等于美学。
- **有效权重和随组变化**：全组有人脸时为 0.85，无人脸时为 0.70；一张漏检会让全组的睁眼维度失效。

### 2.2 两个基础指标测的不是名字说的东西

源码核对（`src/core/metrics.js`）：

| 指标 | 实际算法 | 问题 |
|---|---|---|
| 清晰度 sharpness | 整图缩到 96×96 内，亮度水平相邻像素绝对差的均值（约 L216） | 衡量「画面纹理/对比多不多」，不是「焦点准不准」。人像虚化背景会被当作模糊；大片天空的风光天然低分。原始值 <3 标 `possibly-blurry`；`normalizeMetrics` 对 >1 的值除以 100，存在尺度歧义。 |
| 曝光 exposure | `1 - |meanLuma - 128| / 128`（约 L411） | 偏爱中灰亮度，直接惩罚刻意的低调/高调、夜景风格。 |

### 2.3 测试库实测（run `run-42c86188-ec4c-42e3-9804-a8fd1e91c02c`）

38 个拍摄单元、20 组（10 个多张组、10 个单张组）；10 组检测到人脸，共 22 单元；闭眼全部为 0、flags 全空——**这批数据没有闭眼难例，不能证明闭眼检测有效**。

- 清晰度范围仅 0.06–0.24，曝光 0.47–0.99，质量 0.52–0.75：**排序差异主要由曝光驱动**。
- 人脸面积占画面 0.6%–4%：这批「人像」其实多是环境人像，整图清晰度几乎反映不了脸是否清楚。
- 组 `MV0DD7N2O4NJZ`（红裙/老车，夜景低调）：四张曝光都只有 0.47–0.49（被风格惩罚），第一名 0.4982 vs 第二名 0.4950。**人工样例选的是第二名，并拒绝了模型第一名**（跨 run 同 ID 对照，仅作示例）。
- 组 `MV0DD7O9IQDL5`：首选清晰度更低（0.103 vs 0.123），靠曝光（0.986 vs 0.806）拿到 0.0428 分差被判「把握高」——典型的补偿。
- 组 `MV0DD7O6MFC2P`：无人脸，分差 0.0013；一张更清晰、另一张质量更高，正是应保留双候选的场景。
- 「需确认」阈值 0.03 是固定经验值，不是正确率；10 个多张组有 7 个被标需确认。

### 2.4 学习环节的缺陷

- `pairwiseSamples` 要求四项指标齐全，无人脸照片对全部被跳过。
- `personalize` 的 before/after 在同一批标签上评估，只说明拟合程度，不说明泛化。
- 现有人工决定只有 2 个明确首选组，未达到 5 组启动条件。
- pipeline 在没有组员被建议保留时会强行选一张（fallback），不支持「整组都不合格」。

## 3. Pareto 候选集：可用，但要变体

**优点**：不强行把表情折算成清晰度；能保留「模糊但有美感」「清晰但呆板」各自的代表。

**问题**：

- 目标越多越容易全部非支配。
- 相关指标会重复计票（清晰度与 TOPIQ-NR 高度相关）。
- 指标噪声会让前沿抖动。

**实测**：只用现有清晰度、曝光、质量三项回放，10 个多张组的严格前沿平均 2 张；第一组的前沿包含人工选中的第二名。这只说明候选覆盖，不是审美有效性证据。

**推荐变体**：

1. **硬约束（门槛）**：按类别只淘汰高置信度的不可用照片，例如确认的主体失焦、非意图闭眼、严重遮挡。未知值或检测失败的照片进入人工复核，不自动淘汰。门槛由标注校准，不沿用整图模糊标签。
2. **ε-Pareto**：每类只保留 2–3 个目标，例如「主体可用性 / 表情或瞬间 / 审美」。按每个指标的 ε 分箱后做 skyline，同一箱内只留代表。ε 来自重复预处理的扰动和人工「看不出差别」的标签，不统一设 0.03。
3. **截断与展示**：默认最多展示 3 张。先保护各维度的极值，再按嵌入差异补足代表（多样性，可参考 DPP）；完整前沿可以展开。knee point 只在已校准、低维且有明显折中时使用。
4. **全拒绝出口**：门槛把整组排空时，显示「本组无合格候选」，取消 pipeline 的强选回退。

**注意**：在审美分缺失的情况下，前沿只能称为「技术候选集」，保护不了尚未测量的美感。所以第 5 节的审美恢复是前置条件之一。

## 4. 类别化评分

> 更新（2026-10-10）：四类主类太窄，已改为多维度、多标签、可多选的开放体系，见 [research-scale-learning.md §1](research-scale-learning.md#1-分类体系开放多标签可多选)。下文保留作为默认主类的评分示例。

### 4.1 类别与识别

主类为街拍 / 人像 / 风光 / 其他四类，输出概率；低置信度时允许用户改类。合影、夜景、静物作为**可叠加标签**（夜景人像同时属于两者）。

识别信号：

- **DINOv2 嵌入（已缓存）**：做少样本原型分类，每类约 20–50 张样例。DINOv2 没有文本编码器，不能做文字零样本。
- **CLIP 文本 prompt**：零样本可行，但需要新增模型和缓存，属于额外成本。
- **人脸线索**：人脸总面积占比、最大脸比例、人脸数——是强线索，但不能单独定类（本库人像的脸只占 0.6%–4%）。
- **EXIF**：焦距、光圈、快门作为辅助；EXIF 缺失时要有出口。

### 4.2 每类的目标与门槛

| 类别 | 主要目标 | 硬门槛（高置信度才淘汰） | 不应扣分 |
|---|---|---|---|
| 人像 | 脸/眼局部清晰、表情与眼神、构图 | 非意图闭眼、严重遮挡、主体失焦 | 背景虚化、低调/高调曝光 |
| 风光 | 景物区域清晰、高光与阴影细节、构图与光线 | 全局手抖、关键区域严重过曝 | 天空低纹理、长曝光水流 |
| 街拍 | 瞬间、主体关系、叙事、构图 | 主体完全不可辨且无表达价值（只进复核） | 运动模糊、颗粒、偏暗 |
| 其他/静物 | 主体细节、背景分离、色彩 | 主体失焦 | 背景虚化 |

- **合影**：逐张脸检查，不能用平均睁眼率稀释某个人闭眼。
- **夜景**：放宽整图亮度和噪声要求。

### 4.3 「没把人拍好看」如何操作化

可量化的部分：

- 表情、眼神；
- 遮挡；
- **脸部局部清晰度**（不是整图清晰度）；
- 用户的成对偏好。

**不训练**与身份相关的「颜值」分。闭眼可能是有意表达，表情好坏也依赖用户标签。全组都没拍好时，允许整组拒绝。

## 5. 模糊的区分（替换现有 sharpness）

在代理图上定位脸/眼（已有人脸框）和显著性主体，再回原片按 100% 原生像素裁出局部（代理图上判断不了对焦，见 [research-scale-learning.md §2.5](research-scale-learning.md#25-对焦判断必须用原生分辨率修订于-2026-10-10)），计算多尺度双方向梯度或拉普拉斯方差，同时记录区域尺寸、纹理和噪声可靠性。比较主体和背景：

| 现象 | 判断 |
|---|---|
| 主体清楚、背景低频多 | 背景虚化（不扣分） |
| 脸弱，但同景其他区域清楚 | 主体失焦（人像硬门槛候选） |
| 全图一致方向拖影 | 手抖 |
| 移动主体或背景有定向拖影 | 运动模糊（街拍可能有意） |

快门、焦距和组内邻帧只作辅助。单张图通常无法确定运动模糊是否有意，低纹理和高噪声也会误导判断，所以必须保留「未知」。眼部精细区域需要新增关键点检测。

## 6. 在 Mac 上恢复审美分

1. **首选**：离线用 TOPIQ-IAA（Ray）给 5 千–2 万张图打教师分，在已缓存的 DINOv2 嵌入上训练岭回归，再比较小 MLP。增量推理几乎零成本。
   - 风险：现有的中心裁剪 + 平均 patch 嵌入可能丢掉边缘构图和瞬时表情；教师模型的偏差会传递过来。
2. **对照**：CLIP 审美头（LAION aesthetic v2 风格，实际实现多为 MLP）。CLIP 编码本身不是免费的。
3. **只对候选算重模型**：TOPIQ-IAA 只跑技术候选。需要保留宽松候选或探索样本，避免审美好图先被技术前沿删掉。单张延迟并未因此达标。
4. **类别条件化（theme-aware）**：先用共享审美头加类别交互项，样本足够后再拆成独立头。评估看类别内排序和真实的组内选择，不能只报 AVA 相关性。

## 7. 分阶段路线

| 阶段 | 改动 | 需要的数据 | 验收 |
|---|---|---|---|
| A 可解释候选 | metrics 尺度契约与缺失策略；ranking 新增 ε-Pareto 前沿与「整组拒绝」；pipeline 保留旧排序作对照；UI 展示「各有所长」 | 用户复核现有 20 组：标首选 / 并列 / 全拒绝 / 类别 / 拒绝理由 | 只用于发现问题，不下结论 |
| B 局部指标与分类 | 脸/主体局部清晰度、EXIF、类别模块、版本化门槛 | 200–300 组，每主类 ≥50 组，覆盖闭眼、失焦、虚化、运动难例；类别原型每类 20–50 张 | 前沿召回、误淘汰率 |
| C 审美与个性化 | DINOv2 审美头蒸馏；spot-eval/personalize 支持缺失掩码、类别交互、并列 | 教师样本 5 千–2 万张；约 500 组真实首选 + 难例 pairwise + 平局；按拍摄事件/人物/拍摄者划分冻结测试集 | 下表全部指标 |

对比基线：旧加权、严格 Pareto、ε-Pareto、类别模型。指标如下：

- 组内 top-1；
- pairwise 一致率；
- **前沿包含人工首选的召回率**、前沿平均大小；
- 误淘汰率、全拒绝识别率；
- Mac P95 延迟；
- 类别分项结果，以及组级 bootstrap 置信区间。

待验证目标（不是已达成）：首选召回 ≥95%，前沿平均 ≤3 张。

UI 呈现示例：「这几张各有所长：A 主体最清晰、B 表情最好、C 构图最好」，附脸部放大和风险提示。**没有对应模型证据时，不生成表情/构图优势标签。**

## 8. 文献与证据边界

- **Photo Triage**（Chang et al., SIGGRAPH 2016）：系列内偏好学习，最贴近选片；数据集当前不可得（见 research-culling.md）。
- **TAD66K / Theme-Aware Aesthetic**（He et al., IJCAI 2022）：主题相关审美，支持类别条件化思路；不代表街拍/人像分类已经现成可用。
- **Personalized Image Aesthetics**（Ren et al., ICCV 2017）：支持个体偏好适配；与本仓库的 personalize 方向一致。
- **AADB**（Kong et al., ECCV 2016）：审美属性与排序；**CPC**（2018）和 **GAIC**（2019）只覆盖裁剪构图，不能当作表情或整体选片的真值。
- **Skyline**（Börzsönyi et al., ICDE 2001）与 ε-dominance 多目标工作：为非支配筛选提供基础；**DPP**（Kulesza & Taskar, 2012）和相册摘要中的代表性、多样性方法可用于前沿截断展示。
- **论文库检索结果（负面结论）**：`ml/research/search_genre_corpus.py` 在 Ray 上扫描了 derived 全量加 6 个中文 parquet，共 **359,889 行**（作业 `raysubmit_DHxMhPKgmvjzN98a`，耗时 19 分钟）。关键词覆盖主题感知审美、人像/街拍/风光、属性审美、个性化、Pareto/多目标/skyline、相册摘要、有意模糊/bokeh 等。
  - 去重后命中 2,408 篇，但几乎全部来自 `pareto`、`multi-objective`、`facial expression`、`genre` 等通用词，集中在材料、光子学、天文、人像生成等领域。
  - 标题与照片/审美相关的只有 49 篇，且多为人像生成或重光照（如 SynthLight、Bokeh Diffusion），没有一篇是主题感知审美、照片选择或相册策展的核心论文。
  - 结论：~~该论文库对本方向覆盖不足~~ —— **更正**：本轮脚本只扫了 `derived/` 顶层 2 个文件，而 `derived/` 递归有 24,035 个文件，覆盖率不到万分之一。全量多角度重扫见 [research-scale-learning.md §6–7](research-scale-learning.md#6-论文库检索上次为什么没帮上忙)。

**推断与待验证**：局部模糊归因、蒸馏效果、标注预算和验收目标都是工程假设；当前数据太小且没有闭眼难例，尚不能证明分类或 Pareto 优于旧方法。上述文献的具体版本和许可证未全部核验。

## 9. 下一步（可直接开工）

1. **阶段 A 原型**：在 `ranking.js` 旁新增 `candidates.js`（ε-Pareto 加整组拒绝），pipeline 同时输出旧排序和候选集。在审阅页标出「各有所长」。不改默认写回行为。
2. **复核标注**：用户在审阅页对现有 20 组标首选 / 并列 / 全拒绝 / 类别；需要在 decisions 中增加 `category`、`tie` 字段。
3. **局部清晰度**：用现有人脸框先实现脸部区域清晰度，替换人像组的整图 sharpness；曝光改为「裁切比例 + 类别条件」的门槛，不再奖励中灰。
4. **审美头**：Ray 上用 TOPIQ-IAA 对 AVA 子集（Ceph 已有）和本地库打教师分，在 DINOv2 嵌入上拟合审美头，评估延迟和相关性。
