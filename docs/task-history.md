# 完整任务历史与旧恢复任务定位

新版“任务”页不再只显示最近 8 条记录。历史列表每页显示 20 条，可翻到全部服务记录；页大小只是界面渲染批量，不限制任务总数或照片总数。

“任务历史”搜索框可输入中文任务类型、中文状态或任务编号，例如“恢复”“待确认”“失败”。列表显示中文类型/状态，并标明当前库或其他库；点击任务只查看其记录，不自动执行。原片、标签、星级和文件夹不会因翻页/搜索而改变。

查看旧恢复任务的建议流程：

1. 搜索“恢复”，找到对应任务编号。
2. 点击任务查看完成、跳过、失败和待处理统计。
3. 使用现有 JSON/CSV 导出获取完整异常清单，不把“已处理”混同于所有文件已成功恢复。
4. 只有确认旧执行器停止、当前资源库一致且服务兼容后，才考虑继续/重试；历史展示不会自动接管旧窗口。

# 状态控制响应瘦身（2026-10-09）

任务列表、执行权心跳和断点默认已省略 `items`，不把这些现有轻量路径当作新发现的瓶颈。此次针对仍默认返回完整任务的暂停、取消、配置、完成和失败控制：插件通过 `task-request.js` 显式请求 `?includeItems=false`；服务在提交同样的持久状态变更后只返回任务摘要，不序列化逐项结果。

继续和失败重试仍需要完整计划，不被自动瘦身；GET 单任务、报告导出、显式 `includeItems=true` 以及未传参数的既有控制调用维持原契约。摘要不是删除历史或截断可处理照片数，不更改执行权、排空、安全恢复、日志持久性或 Eagle 元数据。

实际隔离 HTTP 测试：8,000 条合成结果的完整响应为 11,023,393 字节；配置/暂停/完成/失败摘要各 490 字节，取消摘要 493 字节。测试核验末项结果及完整项数仍在持久任务中，配置并发 128 保留，旧无参数调用仍返回全量。测的是合成传输负担，不是实际 Eagle 暂停延迟，也不包括进程内 TaskStore 全量计划占用。

Edge 渲染模拟改为真实省略 `items` 的摘要形状，已有继续、重试、取消、成对审阅及优先审阅回归仍通过；完整 `npm test` 为 137/137、0 跳过。实际运行旧 0.3.0 服务尚未升级，不能把测试改善说成生产界面已生效。
