## 新版行为

分析任务运行时，审阅卡片上的“精选/候选/待复核”和“设为组内首选”可以点击。一次仅处理一个审阅操作，防止重复点击产生重复写回。

插件保持同一资源库只有一个执行器的约束，自动执行：

1. 暂停分析并取消等待中的分析请求。
2. 等待本窗口的真实执行 Promise 完成，包含恢复时的目录预读、在途请求排空、断点保存和执行权释放。
3. 再检查资源库和任务状态；执行权未释放、用户取消/暂停、资源库切换时不抢占、不写回。
4. 创建持久审阅任务，保存确认配对的 JPG/RAW/HEIC/3FR 决定。
5. 只有审阅完整成功且执行权释放后，才恢复此前分析的断点。

这是自动让路，不是分析与标签写入并行。缩略图恢复、角标生成及其他标签写回任务不允许抢占。成对写入仍然不是 Eagle 原子事务；单项失败保留断点，不伪装成功或自动继续分析。

用户在过程中再次主动暂停/取消，或请求重载插件，自动继续会被抑制。未知窗口持有执行权时不会接管。审阅完成后重新读当前人工元数据；旧分析计划发现修改会跳过，而不是覆盖留存决定。因此被人工修改的待分析单元可能需要重新创建分析任务，不会悄悄把“未分析”显示为“已分析”。

## 异步切库与提交保护补充

进一步修复：新版插件的新计划带 `activationPending:true`，小计划创建和大计划封存后都保持暂停。只有显式激活的 `claim` 将任务变为运行并领取执行权，而且两者是同一次持久事务。普通领取、继续、重试不会把待确认计划变成可被其他窗口自动接走的任务。取消及未上传完整的计划不能激活。

新增服务能力 `task-plan-staging-v1`，缺少该能力的服务即使也是 0.4.0 也会被插件拒绝。该规则适用于新版创建的计划，不自动更改既有运行任务；没有把旧任务的状态擅自解释为已安全停止。上传成功但尚未激活时重开插件，计划仍暂停，可以在原资源库任务页明确点击继续。

此阶段完整回归 129/129、0 跳过；真实随机端口 HTTP 测试覆盖 8,000 项封存前后普通执行者均不能领取，持久记录重启后仍待确认、两个显式执行者竞争只成功一个，以及未完整上传/取消计划拒绝激活。浏览器模拟同时要求显式激活字段，验证正常审阅仍可完成。这仍不是实际 Eagle 写回验收。

后续完整回归为 127/127、0 跳过。增加了等待任务所有权查询期间切库的测试：查询返回后重新确认上下文，审阅写入次数为零。

任务创建在第一次网络请求之前加锁，并固定原资源库路径；版本检查、任务历史查询、计划上传后均再次检查资源库及人工控制状态。审阅计划传入其生成时的资源库上下文，不能使用上传时的另一资源库路径。
