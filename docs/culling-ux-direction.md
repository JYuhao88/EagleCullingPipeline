# 筛片界面方向（2026-10-15，草案）

本文记录下一阶段筛片界面的方向，尚未实现。目标是让用户在一组相似照片里，一眼看出该留哪张、为什么、和其他几张差在哪，然后一键决定。现有排序、规则和分组算法不因本文改变。

## 1. 原则

1. **以组为单位，先给结论。** 每组标出建议保留的一张，其余默认进候选或淘汰。用户主要是同意或改掉，不从零挑。按 5/3/1 决定后自动跳到下一组或下一个待看位置。
2. **理由画在图上。** 闭眼放大眼部小图；手、脚被裁断就在画面边缘标出位置；背景亮部抢主体就框出来。能指到部位的问题，才在主界面出现。
3. **只说有把握的。** 没把握的建议不显示。几乎每张都会出现的笼统提示（例如重心）不进主界面。每组最多两三句，每句对应一个具体部位或一处具体差别。
4. **说差别，不说分数。** 主界面用“这张睁眼、那张半闭”“这张手完整、那张手被裁”这类对比句。总分、美感分、详细对比表折叠起来，留给想深挖的人。
5. **先批量收起重复和明显废片。** 几乎相同的连拍只露一张代表；有把握的闭眼、跑焦、关键关节被裁断先收起。剩下真正需要人判断的照片，才让用户逐张看。
6. **安全、可撤销。** 收起不等于删除；所有建议只写星级或标签，随时可展开、可撤销、可清除。

## 2. 一组 20–30 张时怎么处理

### 2.1 先确认“张数”是什么

分组按拍摄单元计算。RAW 和 JPEG 成对时，一个单元在 Eagle 里是两个文件。汕头这批最大的组是 19 个单元，在 Eagle 网格里约 38 个文件，看起来就像一组二三十张甚至更多。

第一步是让配对只算一张：检查器和网格提示都以单元计数，决定时同时作用于配对文件（现有行为已如此）。

### 2.2 把大组收缩成几个“瞬间”

一组 20–30 个单元，通常不是 30 个不同选择，而是几个瞬间或姿势各拍了一串。处理顺序：

1. **按画面相似度切成小簇。** 用已有的画面特征和拍摄时间，把几乎相同的连续几张归为一簇，每簇代表一个瞬间或姿势。簇内用现有测量（睁眼、清晰度、裁切）选一张代表。
2. **有把握的废片收起。** 只收起证据明确的：主体闭眼且同簇有睁眼的、明显跑焦、关键关节被画框切断。没把握的不收。
3. **用户先看代表。** 20–30 张通常收缩为 3–6 个代表。每个代表旁注明“同簇另有 N 张”，可以展开。
4. **代表之间直接比较。** 同屏最多放 2–4 张，配一句差别说明。不需要逐张从头翻到尾。

这样一个大组的工作量，从看 30 张变成比较 3–6 张，必要时再展开某一簇细看。

### 2.3 每组留几张

- 默认每个瞬间留 1 张，整组建议保留数可以设置（例如 1–3 张）。
- 表情、姿势确实互补时可以多留，例如同一场景里笑和不笑各一张。这类情况只作提示，不由算法强行限制。
- 超过保留数的代表默认进候选，不是淘汰；用户随时能改。

### 2.4 大组往往说明分组太粗

20–30 张经常混了不同场景或不同人物组合。检查器在大组上提示“可能是几段不同的拍摄”，并给出拆分建议，由用户确认后再拆（复用现有的分组修正功能）。不自动拆组。

### 2.5 键盘流程

1. 进入大组，先看到收缩后的 3–6 个代表和每簇张数。
2. 左右键在代表之间切换，5/3/1 决定；空格展开当前簇。
3. 本组看完，回车接受剩余建议并跳到下一组。

## 3. 现有能力与差距

| 需要的能力 | 现状 |
|---|---|
| 配对按单元计数 | 已有 |
| 画面相似度 | 已有“与第 1 名相似度”和画面特征，未用于组内切簇 |
| 睁眼、关节裁切、曝光测量 | 已有，可作为收起依据和图上标注来源 |
| 组内代表选择 | 已有组内排名，未按簇分别选代表 |
| 图上标出问题部位 | 未做；关键点和人脸框已有，可直接定位 |
| 两张之间的一句话差别 | 已有差异列表，需改成具体部位的对比句并过滤笼统项 |
| 拆分建议 | 已有手动分组修正，未做大组提示 |

## 4. 落地顺序

1. 组内切簇与代表（不改总排名，只改展示方式和默认展开状态）。
2. 图上标注闭眼、关节裁切、亮部抢主体。
3. 代表之间的对比句，过滤没把握的提示。
4. 大组拆分提示。

每一步先在汕头这批上自检：大组收缩后的代表数、被收起照片里人工发现的误收数。误收明显时不上线收起功能，只保留标注。

## 5. 宿主调研（2026-10）

**Eagle**：插件只有窗口、右侧检查器、新格式预览器三种入口。网格没有堆叠，不能在 Eagle 大图上叠加标注，没有并排比较，也没有挑选/淘汰标记。插件窗口是网页界面，可以自由布局，窗口接口有 `setAlwaysOnTop`、`showInactive`、`setBounds`、`maximize`。

**Lightroom Classic 插件接口（Lua）**：

- 可以写星级、挑选/淘汰标记、色标、关键词、收藏夹、插件自定义字段（能在智能收藏夹里筛选），可以设置选中照片，能取 JPEG 预览，能用 HTTP 与本机服务通信。
- 可以打开一个非模态浮动窗口：显示缩略图和图片，监听选中变化。控件比网页简单很多。
- 不能给已在目录里的照片建堆叠或改堆叠，不能在大图上叠加标注，不能读像素（只能取预览）。未见读取“辅助筛选”分数的公开接口。

**Lightroom 云端 API**：2026-07-31 已停止服务，不考虑。

**Lightroom Classic 自带的辅助筛选**：眼部和主体对焦、睁眼（判断不了的标为“无法判断”）、按时间或相似度自动堆叠、堆叠内按美学排序选首张，均可手动调整。需要订阅。

**专业筛片软件**：Aftershoot（本地、自动化程度高）、Narrative Select（人脸特写并排比较最好，适合人像）、FilterPixel（云端、快，每张给分数和理由）、Photo Mechanic（纯手动快速浏览）。核心都是“分组 + 眼部/对焦/表情 + 代表图”，基本没有姿态和构图建议，也不开放插件接口，只能通过星级、标记或 XMP 交接。

**选型理由**：

- 照片可以随时导出，宿主不构成锁定；选 Eagle 是因为它已经接通，浏览功能成熟，公开接口还有余量。
- 本项目的差异在姿态和构图建议、可解释的组内差别、个人口味学习、全部本地运行，与宿主无关。
- 以后需要接 Lightroom 时，只加一个写回适配。

**结论**：浏览交给 Eagle，不另做浏览器或独立网页。先用 Eagle 的公开接口把结论送进 Eagle 自己的界面（见 5.2），只有 Eagle 确实做不到的组内并排比较，才在检查器或一个小比较窗口里补上。Lightroom 的优势是原生堆叠、挑选标记和 XMP，适合作为可选的写回目标，也可以拿它的辅助筛选当基准。

**其他工具**（照片可以随时从 Eagle 导出，宿主不构成锁定）：

| 工具 | 类型 | 筛片能力 | 可扩展性 |
|---|---|---|---|
| Capture One 16.8 | 商业 | 辅助审阅（测试版）：标记闭眼、失焦、黑帧 | 插件 SDK 只覆盖导出后处理，没有筛片接口 |
| digiKam | 开源 C++/Qt | 图像质量排序、人脸 | 可改源码，但体量大、构建重 |
| darktable | 开源 C + Lua | 手动筛选 | Lua 能加模块和批量操作，不能在图上叠加标注 |
| Immich | 开源 TypeScript，自托管 | 原生堆叠、相似搜索 | 开放接口，可改，但要部署服务端和数据库 |
| Facet | 开源本地筛片引擎 | 多维打分、连拍分组、自动筛选预演、网页图库 | 写 XMP，带 Lightroom 插件，可同步 Immich |
| selects | 开源 Python（MIT） | 连拍选最佳、并排同步放大比较、口味学习 | 接口优先，写 XMP |

Facet 和 selects 的形态与本项目最接近：独立的本地分析服务加网页筛片界面，通过 XMP 或插件与 Lightroom、darktable、digiKam、Immich 交接。它们证明“自己的筛片界面 + 宿主只做照片库”是可行做法，可以参考它们的比较页和键盘流程。

### 5.1 能否改 Eagle 本体

用逆向分析工具 REA 对 Eagle 4.0.0 做了只读静态分析：

- Eagle 是 Electron 应用。主进程编译成 V8 字节码（`.jsc`），基本无法修改；主窗口界面（Angular 1）和插件接口是明文 JS。
- Electron 安全开关：未开启 asar 完整性校验，允许调试参数。技术上可以修改 `app.asar`，或以调试模式启动后向主窗口注入脚本。
- 不建议这样做：
  - 修改安装包会破坏 macOS 签名；
  - 每次 Eagle 升级都会覆盖改动；
  - 主窗口内部结构没有任何兼容承诺；
  - 开调试端口有安全风险；
  - 可能违反 Eagle 使用条款，也不能放进公开仓库。
- 分析中找到几项**已公开但本项目尚未使用**的接口，可以补上部分短板：
  - `contextMenu`：在 Eagle 右键菜单加入“在筛片窗口比较”等入口；
  - `smartFolder`：按簇或按建议生成智能文件夹，部分代替堆叠；
  - `item.setCustomThumbnail` / `refreshThumbnail`：在网格缩略图上画问题标记，可恢复原缩略图；
  - AI Search（`searchByItemId`）：Eagle 内置的以图搜图，可以作为相似度的交叉参考。
- 插件运行在带 Node 能力的渲染进程中，现有能力已经足够做完整的筛片窗口，不需要改 Eagle 本体。

### 5.2 与 Eagle 的分工：不重复造轮子

**Eagle 负责、本项目不做**：网格浏览、大图预览与放大、资源库和文件夹导航、搜索筛选、元数据编辑、RAW 解码与渲染、缩略图生成。

**本项目只补 Eagle 没有的**：分析结论（簇、代表、问题部位、差别说明）、组内 2–4 张并排比较、按组推进的决定流程。

**优先把结论送进 Eagle 自己的界面**，用的都是公开接口：

| 需要 | 在 Eagle 内的做法 |
|---|---|
| 图上标注 | Eagle 的区域批注（`item/addComment`，已试用，见 5.4）；自定义缩略图画标记作为备选 |
| 簇与代表 | `AI·代表` / `AI·同簇` 标签加智能文件夹（已试用，见 5.4） |
| 进入比较 | 右键菜单“与同组比较” |
| 定位照片 | `item.select` 让 Eagle 选中并预览 |

**自己做的界面只保留比较**：放在现有检查器，或一个小比较窗口。图片直接用 Eagle 的缩略图和原图地址，不自己解码；点任何一张都回到 Eagle 预览。没有网格、没有导航、没有放大查看器，也不提供浏览器独立打开。

**判断标准**：先只用 Eagle 内的做法试一批组。如果标注缩略图加智能文件夹已经够用，就不做比较窗口。

### 5.3 比较窗口不被 Eagle 主窗口挡住（仅在需要比较窗口时）

1. **比较时窗口放大。** 沿用现有“放大窗口”，比较和决定在本窗口内完成，结束后回到 Eagle。
2. **需要与 Eagle 并排时提供“置顶”开关。** 调用 `setAlwaysOnTop(true)`，并用 `setBounds` 贴在屏幕一侧。默认关闭；退出筛片、完成本任务、窗口隐藏时自动关闭，避免挡住其他办公软件。
3. **不抢焦点。** 从 Eagle 选中照片联动到窗口时用 `showInactive`，用户在 Eagle 里操作时键盘不被窗口接走。
4. **上线前实机验证。** 需要在 macOS 和 Windows 上分别确认：置顶在 Eagle 全屏或独立桌面空间下是否生效，以及最小化 Eagle 后窗口的行为。

### 5.4 试用：只用 Eagle 已有功能（2026-10-15，本机资源库一次任务）

脚本 `scripts/eagle-native.mjs` 读取一次已完成任务的结果，通过 Eagle 本机 HTTP 接口写入三样东西。照片文件和 Eagle 本体都不改。

| 写入 | Eagle 里怎么看 | 本次数量 |
|---|---|---|
| 区域批注：问题部位画框并附中文说明 | 预览大图时打开工具栏的“批注”开关；有批注的照片按钮上有数字 | 170 张照片，296 条 |
| 标签 `AI·代表` / `AI·同簇` | 标签筛选或智能文件夹 | 代表 60，同簇 130 |
| 智能文件夹 | 左侧“智能文件夹” | 2 个 |

- **收起重复。** 只对 8 个及以上照片单元的组做相似聚簇（组内向量、平均连接、阈值 0.1）。本次有 8 个组被拆成小簇，例如一组 19 张收成 5 簇、一组 17 张收成 4 簇，每簇分数最高的一张标为代表。智能文件夹“AI·筛片：收起重复后”的条件是“在任务文件夹内”且“不含 `AI·同簇`”，506 张收成 376 张。
- **问题标注。** 只标主体，只用规则已经判定的结果：主体闭眼画眼睛框，关节处裁切画关节点，主体模糊画人物框。智能文件夹“AI·筛片：有问题标注”的条件是“批注包含 AI·”，共 170 张。
- **可撤销。** 写入时记一份台账（`data/cache/eagle-native/<任务>.json`），`clear` 按台账删除批注、标签和智能文件夹，不碰用户自己的标签和批注。实测写入后清除再写入，资源库可以恢复干净。
- 用法：`node scripts/eagle-native.mjs plan|apply|comments|clear <任务 ID>`。`plan` 只打印、不写入；`comments` 只替换批注，标签和智能文件夹不动。

**试用中修正的问题**

1. 背景人物闭眼被标成问题。改为只用规则对主体的闭眼判定，并要求脸框落在主体框内。
2. 风景照被标“主体偏小”，没有意义，已删除这一类。
3. 裁切说明原来是“右沿距手腕 0.3 头高”这类内部用语，改成“画面右边卡在手腕附近”“脚被画面下边切掉”。
4. 智能文件夹如果限定任务文件夹，会漏掉 76 张未归档的照片。问题文件夹因此不加文件夹条件，只看批注。
5. 一条裁切规则判违规时，旧脚本会把这个人所有贴边的关节都画框，并挂上同一句说明。现在每条规则只标自己的关节（手腕规则只标手腕和手指），每个框写自己的说明，例如“左膝盖被画面下边切掉”。库里的批注已原地替换，共 304 条。
6. 已知限制：现有“写回 AI 标签”会先清掉全部 `AI·` 标签再重写，会把代表/同簇标签一起清掉。正式接入前要么改用不同前缀，要么让写回跳过这两个标签。

**结论**：簇与代表、问题部位这两类信息，用 Eagle 自带的标签、智能文件夹和区域批注就能表达，不需要自己做网格或标注层。还没试的是右键菜单入口和自定义缩略图标记。是否还需要比较窗口，要等用户在 Eagle 里实际挑过几组后再定。

### 5.5 看细节时调曝光

**Eagle 做不到。** Eagle 4 的预览只能缩放，没有曝光或亮度调节。插件接口也没有给预览加滤镜的入口。格式扩展插件只接管 Eagle 不支持的格式，接管不了 JPG 和 RAW 的预览。改 Eagle 本体按 5.1 不考虑。

**做法：在检查器里加一个只影响显示的局部预览。** 检查器侧栏新增折叠块“细节与曝光”，Eagle 主预览不变：

- 默认 2× 放大，对准主体的脸；没有脸时对准头部关键点，再没有就对准画面中心。可以切换适应 / 2× / 4×，点图片换放大位置。
- 曝光滑杆 −3 到 +3 EV，步长 0.1。按线性光计算，+1 EV 就是亮度翻倍，与相机的档位一致。
- “自动”按当前看得到的区域测光，把中间亮度推到 18% 灰；“复位”回到 0。
- 图像取自本机服务已有的显示图接口，按框大小、放大倍数和屏幕像素比取图，不另外解码原图。
- 只改这块区域的显示，不改原图、不改 Eagle、不进评分，也不写入决定。放大倍数、曝光和展开状态记在本机，切换照片时保留。

**验证**：单元测试覆盖曝光换算、自动测光、对焦点和取景位置。用真实任务的数据在浏览器里实测过 2× 对脸、自动测光（+0.3 EV）、+1.5 / −1.5 EV 和 4×。Eagle 里的检查器已加载新代码，折叠块出现在侧栏底部，默认收起。

### 5.6 Eagle 官方 AI Action 插件能否用于筛片

**它是什么。** 官方插件（1.0.3，2026-09），依赖 AI Models 插件里配置的视觉模型（云端接口或本地模型）。用户把若干步骤组合成一个“动作”，可绑快捷键，对选中的照片批量执行。可选步骤有：改名、写描述、打标签、归入已有文件夹、打星级、清空信息。每一步可以写自定义说明。执行中途可以一键撤回已完成的改动。装了 AI Search 后，打标签和归文件夹会参考相似照片已有的整理方式。

**对筛片的核心环节帮助不大**，原因如下：

1. **逐张判断，不做组内比较。** 筛片要回答的是“这一组里留哪张”，属于相对判断。AI Action 每张图单独送给模型，看不到同组其他照片。AI Search 只给打标签和归文件夹提供参考，打星级用不上。
2. **星级会冲突。** 它的“打星级”直接写 Eagle 的星级字段，和用户自己的决定、本项目的星级同步抢同一个字段。同一张图换个模型或重跑一次，分数也可能变。
3. **没有位置信息。** 只能输出文字、标签和星级，给不出闭眼、裁切的位置框。本项目的规则判定加区域批注（见 5.4）更准，也能定位。
4. **成本和隐私。** 每张图调用一次视觉模型，几百张一批就是几百次调用。用云端模型时照片要上传；本地模型官方建议至少 12 GB 显存，并且不推荐用本地模型做打标签和归文件夹。

**适合用在筛片之后**：对留下的照片改名、写描述、按内容打标签，方便以后搜索。这些属于整理，不属于挑选，和本项目不冲突。

**使用时的约束**

- 不要在待筛的文件夹上运行带“打星级”或“清空信息”的动作。
- 打标签时避开 `AI·` 前缀，免得和本项目的标签互相覆盖。
- 不做纯标签动作的快捷键来代替决定按钮。决定要进本项目的记录，才能续跑、写回和学习口味。

**AI Models 本身可能有用。** 它给插件提供统一的模型调用接口（`eagle.extraModule.ai`）。如果以后要在用户本机做“为什么选这张”的文字说明，可以复用用户在 Eagle 里配好的模型，不用另外管理密钥。目前项目的模型调用都在后端完成，暂不需要。

### 5.7 评分以外的 AI 建议（2026-10-16）

用户试用后的反馈：除了评分，几乎看不到别的 AI 建议。原来检查器只有一句“比第 1 名总分低 2 分，各项差别都不大”，理由字段是分项分数，而且默认折叠。

之前的调研（`docs/advice-eval.md`）说明，规则写出的建议复述不出专家指出的问题；模型当裁判在两张之间挑，大多是平局。所以两层都只说“差在哪”，不说“该留哪张”，不改排序。

**第一层：本机对比句（已上线到检查器）**

- `src/core/photo-facts.js` 为每张照片整理主体的事实，只取规则判定或测量已经支持的项：睁眼或闭眼、哪些部位被画面边切到、可能模糊、眼部和脸部清晰度、主体亮度、脸上高光溢出、画面歪。
- 检查器把当前照片和它的对手比较：对手是第 1 名；当前就是第 1 名时，对手是第 2 名。每张最多显示 3 句，按睁眼、裁切、模糊、清晰度、高光、亮度、水平的顺序取。✓ 表示这张更好，✗ 表示更差，· 只是事实。
  - 例句：“✗ 膝盖、脚被画面边切到，第 1 名没有”“✓ 眼部比第 1 名清楚”“· 主体比第 1 名暗约 1 档”。
- 只说明显的差别：清晰度相差 1.3 倍以上，亮度相差 0.7 档以上，脸上高光一边超过 2%、另一边低于 0.5%。没测到的项不说。没有任何对比句时，才退回原来的总分差那句。
- 汕头这次任务里，多张组的 244 张照片中有 176 张至少有一句对比。最常见的是眼部清晰度（125 句）和裁切（63 句），闭眼差别 15 句。

**第二层：模型观察（离线试验，未接进界面）**

- 脚本 `scripts/model-notes.mjs` 只处理收起重复后的大组。每组把簇代表（最多 4 张）缩成长边 768、去掉元数据的 JPEG，连同第一层的测量一起发给视觉模型，每组一次调用。
- 要求模型只补充测量看不到的东西：表情神态、视线、手和姿势是否自然、背景杂物或穿帮、主体和背景是否分得开。每条要说出部位，不打分、不挑赢家、不重复测量；每张最多 2 条，另给一句组内最主要的区别。
- 结果缓存在 `data/cache/model-notes/<任务>/`，每组生成一张对照图供人工判断。用户确认有用之后，才考虑接进检查器，并标成“AI 观察”，和对比句分开显示。
- 运行方式：本机安全软件会拦截 node 访问模型服务，所以调用放在 Ray 上。分三步：
  1. `node scripts/model-notes.mjs prepare <任务>`：在本机生成请求；
  2. `python3 scripts/aihub-ray.py submit|status|collect`：提交一个只用 1 个 CPU 的作业，从作业日志收回结果；
  3. `node scripts/model-notes.mjs ingest <任务>`：记账，并出对照图。

  密钥只放在作业代码包内的单独文件里，不进作业的环境变量（Ray 面板的作业列表会显示环境变量），日志里也只有结果和用量。提交时会检查本项目同时运行的作业不超过 2 个。

**第一次试验结果（汕头 8 个大组，gemini-3.8-flash，共 0.41 元，8 组全部成功）**

- 模型说出了测量给不出的东西：
  - 路人入镜，例如“左侧背景有低头看手机的路人”“左下角有走动的小女孩入镜”；
  - 视线方向，例如“视线看向画面右侧，未看镜头”；
  - 表情，例如“嘴唇微张，表情略显僵硬”“面部微笑露齿”；
  - 手势，例如“右手食指轻点下巴”“左手叉腰”；
  - 主体和深色背景粘连。
- 抽查两组对照图，基本属实；个别视线判断偏差，比如接近正视镜头被说成看向右侧。
- 也有重复测量的情况，例如欠曝、过曝，提示词里已经要求不要重复。
- 每组那句区别比较笼统，多是“手部动作、视线方向和表情不同”，用处不如每张的具体观察。
- 是否接进检查器，等用户看过对照图再定。如果接，只显示每张的观察，标成“AI 观察”，和本机对比句分开；结果按任务缓存，不在挑片时实时调用。
- 用户希望使用时完全不调用接口。蒸馏到本地小模型的方案、验收门槛和预算见 [research-local-observations.md](research-local-observations.md)。

## 6. 边界

- 不改排序权重、规则和分组算法；收起只影响默认展示。
- 不自动淘汰或删除照片；收起的照片仍是候选，可以展开。
- 美感参考分和内容标签不作为收起依据。
- 个人口味学习仍等用户认真挑过一批组之后再做。
