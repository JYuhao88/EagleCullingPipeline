# 500 文件只读分析验收

## 命令与范围

```powershell
node scripts/audit-real-analysis.mjs --semantic --adjacent --high-quality --per-format 125
```

从当前 Eagle 库 JPG/ARW/HEIC/3FR 的最大文件夹中各取按文件名排序的前 125 个文件。500 文件合并为 250 个拍摄分析单元；使用确认配对的成片预览分析，不重复解码 RAW。没有修改 Eagle 标签、星级、文件夹、缩略图或原片。

报告写入独立临时目录：`C:/Users/Yuhao/AppData/Local/Temp/eagle-real-analysis-yDMGb1/report.json`，生成时间 UTC `2026-10-08T19:56:48.930Z`。每个被选中原片和实际分析来源均进行分析前后 SHA-256 与元数据字节校验。

## 首次失败与修正

首次同规模运行真实触发了 60 秒连接超时，没有生成成功报告。不能把该次运行算作通过。

检查发现服务在单个请求内逐项 `await` 预处理，已有资源调度器的并行容量没有用于该批次。现改为通过内存感知调度器并行准备，保留输入顺序；出现预处理异常时取消待处理项，等待活动解码排空，再报告错误。没有启动更多模型副本。

审计请求按至多 32 个单元的小批发送，并继续按 UTF-8 字节限制分块，复用同一组模型与缓存。32 是连接内工作批量，不是用户选择总数限制。全体结果通过临时服务的分块计划上传持久化，再按任务引用执行全样本聚类，避免巨大向量 JSON 超出 HTTP 请求预算；没有把相似组按请求批次切开。临时计划始终未激活，不会写 Eagle。

## 当前评分 v3 + 进程树监测复测

上述修正后结果是历史运行。现已另用 `scripts/measure-analysis-resources.ps1 -PerFormat 125` 对同类 500 文件/250 单元进行只读复测，报告 `C:/Users/Yuhao/AppData/Local/Temp/eagle-real-analysis-chYhra/report.json`，UTC `2026-10-08T20:33:12.979Z`。首次/重复/聚类暂存为 36,129 / 6,548 / 306ms；500 个原片 SHA 和元数据全部未变，失败 0。所有评分版本为 `preview-v3-technical-only`、主体/构图空值，250 向量有效且重复一致，250 次缓存命中。

本轮 203 个场景组、42 个多图组，最大 4 个拍摄单元；组内首选受新技术粗排影响，但没有人工准确率真值。142 个检出人脸仍不等于闭眼或主体质量正确率。Node RSS 观测峰值 636MiB；此次补齐进程树监测，工作集/私有内存观测峰值为 1,274 / 1,549.1MiB。采样、GPU 共享负载和累计 CPU 口径详见 `resource-measurement.md`，不能把这些值承诺为全库资源上限。

## 不能由此得出的结论

- 首次分析是新模型会话和空工具缓存，不是操作系统磁盘缓存全冷；失败运行已经读取过同一批照片。
- 重复分析仍计算基础质量和人脸，不是所有计算都跳过。
- 674MiB 只属于 Node，不包含 Python 模型或 GPU；不能把 20 文件的进程树测量直接套到这里。
- 142 个检出人脸不等于正确率或闭眼准确率；没有人工真值，不能宣称筛选建议已准确。
- 连续文件抽样不是全库随机代表样本；复杂多人、极端宽高比等仍需单独验收。
- 此次是随机端口只读模型/缓存/聚类验收，尚未完成真实 Eagle 500 文件写回、UI 操作或全库持续负载验收。
- 当前生产服务仍为旧版，原生预览和旧角标恢复也未因该测试自动完成。
