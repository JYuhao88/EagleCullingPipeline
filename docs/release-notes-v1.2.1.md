# v1.2.1 发布说明

修复 Windows 上依赖变化时自动更新失败的问题。排序、规则、评分模型和依赖均未改变。

## 修复

- 依赖按 lockfile 哈希安装到独立目录，仓库根 `node_modules` 改为指向当前依赖的目录联接（Windows）或符号链接（macOS）。
  更新时只切换链接，不覆盖运行中服务已加载的原生模块（例如 sharp 的 DLL）；回退直接指回上一版依赖，无需重装。
- 已有安装的真实 `node_modules` 目录会在首次更新后自动迁移为上述结构，原目录保留。
- 保留当前与上一版依赖目录，按时间清理更早的目录；清理失败不影响更新结果。
- 切换前失败时不会删除现有依赖目录；候选服务启动失败时旧服务继续可用。
- 发布说明：依赖未变时不修改 `package-lock.json`。

## 验证

- Windows 真机演练：真实目录 → 只改版本 → 连续三次 lockfile 变化，服务运行且 sharp 已加载时均更新成功；回退成功；候选启动失败时旧服务可用。
- 完整回归通过，公开检查 0 命中。
