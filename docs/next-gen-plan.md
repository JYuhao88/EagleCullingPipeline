# 下一代方案：专家规则 + 多模态老师 + 个人偏好（2026-10-10）

> 更正：汕头与 Eagle 原样片没有摄影师精选，旧「比随机差」结论已撤销（[eval-shantou-20260718.md](eval-shantou-20260718.md)）。当前排序效果需用 T-syn、T-triage 与专家档位重新建立基线。
> 方向：把专家长期积累的经验写成**可检查的规则库**；能直接测量的规则用代码测量，测不了的交给**多模态大模型带着规则离线点评**；再把老师的判断蒸馏到本地小模型，最后用摄影师本人的选择校准权重。
> 测试方案：[test-plan.md](test-plan.md)。人像信号细节：[research-portrait-body.md](research-portrait-body.md)。

## 1. 原则

1. **规则可追溯**：每条判断都能指到具体规则和出处，界面上直接显示「裁在膝盖（P-CROP-KNEE）」。
2. **规则可破**：每条规则都能按类别关闭，也能单张豁免。豁免会被记成个人偏好，而不是当作模型错误。
3. **永不误删**：只给建议、排顺序；拒绝必须由用户确认，写回可撤回（现有能力保留）。
4. **本地优先**：日常选片全部在本机完成。老师只在前期少量调用 Codex 或 可配置多模态服务 打标签，不部署大模型；只发缩略图和必要的局部截图。
5. **每步可验证**：任何改动都要在有可靠真值的基准上与随机和按拍摄顺序这两个基线比较（[test-plan.md](test-plan.md)）。

## 3. 规则库

### 3.1 格式

每条规则：`id`、`aspect`（framing / hands / pose / face / background / exposure …）、`statement`（可读规则）、`check`（`measure` 代码测量 / `teacher` 老师判断 / 两者结合，附信号名和阈值）、`severity`（`gate` 门槛 / `penalty` 扣分 / `hint` 仅提示）、`exceptions`、`sources`。见 [`src/rules/portrait.json`](../src/rules/portrait.json)，格式由 `test/rules.test.js` 校验。

### 3.2 怎么建

1. **收集来源**：你认可的书籍和教程、你自己的选片习惯、你给的参考图（已用于人像裁切规则）。
2. **抽取**：用大模型从书籍章节里抽取候选规则（陈述、适用题材、例外、原文页码），统一成上面的格式。
3. **你审核**：逐条确认、修改、删除，并标出「我常故意破的规则」。
4. **配样例**：每条规则配 2–4 张正例和反例（优先用你自己的照片），既是文档，也是老师和测量代码的回归测试。
5. **版本化**：规则库带版本号，每次评估记录用的是哪个版本。

### 3.3 覆盖计划

| 题材 | 第一批规则方向 |
|---|---|
| 人像（v0.1 已有） | 头顶留白、关节不切、景别档位、手、重心与肩髋、断肢、睁眼、焦点在眼、表情、背景穿头、人脸曝光 |
| 街拍 | 决定性瞬间、层次与前中后景、人物与几何关系、动态模糊是否有意 |
| 风光 | 地平线水平与位置、前景、光线时段、天空与地面的曝光平衡、引导线 |
| 活动/多人 | 关键人物与关键瞬间、多人中任一闭眼、遮挡、合影站位 |
| 通用 | 主体明确、边缘干净（无半截杂物）、焦点在主体、高光裁切 |

## 4. 多模态老师

### 4.1 输入与输出

- **输入**：2048 全图；人脸、手、对焦点的原生分辨率 100% 局部；L0 测量值（例如「下沿距膝关节 0.05 头高」）；题材对应的规则清单。
- **输出**（JSON）：逐条规则的 `pass / warn / violate / n.a.` + 一句证据；整体建议（保留 / 候选 / 拒绝）；同组两两比较时给出「A 优于 B」及主要原因。
- **为什么做两两比较**：大模型给绝对分不稳定，比较同组两张更可靠；比较时交换左右顺序各问一次，消除位置偏差。
- **为什么给测量值**：防止幻觉。「是否切在膝盖」以关键点测量为准，老师只负责测量做不了的部分（表情、手是否自然、背景穿头、氛围）。

### 4.2 老师从哪来

**决定（2026-10-10 修订）**：不部署大模型（Ray 上也不部署）。前期打标签用现成的服务，**少量、按需**调用：

| 来源 | 用法 | 说明 |
|---|---|---|
| Codex（经本机 codex-lb） | 文本为主：从衣刀视频转写中抽取逐张点评、档位、规则候选；跨期汇总规则。需要看图时用 `codex exec --image` 附截图 | 已有通道，适合批量文本抽取；看图任务控制数量 |
| 可配置多模态服务（少量） | 多模态逐条点评和组内两两比较：汕头、Eagle 原样片，以及规则正反例 | 只用于真正需要看图判断的部分，按预算调用 |

调用规则：
- **先测量后提问**：能用关键点、对焦、曝光测量的规则不问模型；只问表情、手是否自然、背景穿头、氛围这类测量做不了的。
- **缓存**：按（图片哈希、规则版本、prompt 版本、模型）缓存结果，同一问题不重复调用。
- **预算**：每批先抽样 20–50 张试点，在 T-syn／T-triage／专家点评上确认一致性后再扩大；每次调用记录数量和耗时到 `ml/teacher/usage.jsonl`。
- **隐私**：只发 2048 缩略图和必要的局部截图，不发原片；你的私人照片发送前单独确认范围。

本地部署（RTX 4070 Ti Super，16 GB 显存）只放小模型：

| 部分 | 内容 | 显存 |
|---|---|---|
| 测量层 | RTMW 全身关键点 + YOLOX 检测（ONNX，DirectML / CUDA / CoreML / CPU） | < 1 GB |
| 本地排序（学生） | DINOv2-small 特征 + L0 信号 + 小型 MLP 头 | < 1 GB |

日常选片不依赖任何在线服务。是否以后再加一个本地小型点评模型，等学生模型的效果出来再定。

### 4.3 先验证再用

老师本身也要过 [test-plan.md](test-plan.md) 的门槛：用 T-syn 的受控退化、T-triage 的众包偏好和有出处的专家档位验证保留建议、两两偏好与逐条规则。汕头 253 张仅为无标签源图，不能用于精选 AUC／召回。超过当前基线和简单规则组合之后，才用来蒸馏；用户无需补做标注。

### 4.4 蒸馏

老师只在抽样的样片和规则正反例上运行（数量受预算控制），产出逐条结论和两两偏好；公开数据集（CADB、PCCD 等）本身带人工标签，直接作为补充训练数据。学生模型用 DINOv2 特征 + L0 信号学习这些标签，部署在本机。老师不进入日常选片流程，也不提供在线「第二意见」，避免日常使用依赖网络服务。

## 5. 下一代功能

按价值排序：

1. **两段式选片**：先「剔废片」（糊、闭眼、焦点打偏、坏切），再在剩下的里「挑精选」（候选集，允许一组多张）。
2. **理由与规则引用**：每张卡片列出命中的规则；点击可看规则说明和正反例。
3. **叠加层**：裁切参考线（类似你那张红绿线图：绿线为合格切点，红线为关节危险区）、骨架、相机对焦点、人脸和手的框。
4. **1:1 放大镜**：同组眼部、手部 100% 局部并排比较。
5. **规则开关与题材 profile**：每次拍摄选题材（可多选）；单张「我故意的」一键豁免。
6. **按问题筛选**：「只看坏切」「只看焦点打偏」「只看闭眼」，批量处理。
7. **拍摄复盘**：本次拍摄的常见问题统计（例如「23% 切在膝盖，集中在 16mm 段」），帮助摄影师改进技术。
8. **学习与 profile**：每次选片自动成为训练数据；偏好随时间漂移时提示，可回滚。
9. **渐进处理**：导入后后台预处理，按时间窗口逐段出结果，万张规模不必等全部跑完。
10. **规则化点评**：根据规则结论自动生成一句中文点评（模板 + 学生模型输出），不依赖在线模型。

- 卡片角标只用三种：推荐、各有所长、有问题。具体原因放在规则面板，不挤在卡片上。
- 「剔废片」模式按问题分组批量确认；「挑精选」模式逐组浏览候选。
- 所有 AI 结论都可以一键反驳，反驳会写进事件日志，供个人层学习。
