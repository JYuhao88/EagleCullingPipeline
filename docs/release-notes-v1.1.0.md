# v1.1.0 发布说明

v1.1.0 在 v1.0.0 基础上补齐大规模结果加载、真实 Eagle 只读验收和两项审阅功能。
排序、规则和评分模型未改变；同平台合成基准三项指标与逐行结果均与 v1.0.0 一致。

## 新增与改进

- 大规模结果：新 run 以分段 JSONL 加偏移索引保存，按组/单元按需读取，不再物化完整结果。
  旧 `results.json` 只读兼容。合成 10 万单元下首屏接口约 380 ms、单组约 16 ms、峰值 RSS 约 525 MiB。
- 分页与流式导出：`/runs/:id/groups`、分页 `/results`、`/decisions`、`/report`；
  审阅页每页 20 组并支持翻页；报告可分页或流式导出全部 JSON/CSV。
- 阶段检查点、取消与续跑：扫描、指标、嵌入、人脸、姿态、原生焦点、分组和排序按阶段保存；
  `POST /runs` 传 `resumeRunId` 可续跑；取消在当前原生调用返回后生效。
- 自由文本理由：保留/淘汰时可填写不超过 500 字的理由，写入决定、事件和报告；输入时快捷键不触发。
- 眼部定位补全：人脸检测缺少眼部框时，复用姿态关键点补全眼部 ROI；
  低置信度或多人匹配歧义时放弃，不生成闭眼分数。
- 真实 Eagle 只读验收脚本：通过只转发 GET 的代理运行完整流程，任何写请求都会使验收失败，
  并核对原片 SHA-256 前后一致。
- 基准测试可放到远端集群冷算：`scripts/bench-ray.py` 打包、提交、回收并校验缓存签名与模型哈希；
  `EAGLE_BENCH_CACHE_ONLY=1` 拒绝本机冷算。

## 已知限制

- 跨平台数值差异：不同平台的姿态关键点置信度可能在阈值附近有微小差异（例如 0.2994 与 0.3003），
  导致少量合成对结果不同。质量门槛必须在同一平台上比较。
- 10 万单元规模测试使用合成特征，不包含真实模型全流程推理、浏览器渲染耗时或冷磁盘测量。
- 眼部定位补全的人工准确率核对尚未全部完成；对焦命中仅表示 AF 点与眼部 ROI 相交。
- 候选集和偏好学习仍默认关闭，尚未经真实用户选择验证。v1.0.0 的其余限制仍然适用。
